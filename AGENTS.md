## Project Overview

Poring is a small IRC bot written from scratch. It connects to an IRC server, translates IRC messages into typed events, and implements bot behavior through event listeners.

- Runtime: Node.js 26
- Language: TypeScript 7 with strict type checking
- Modules: ESM with NodeNext resolution
- Package manager and build: npm and `tsc`
- Entry point: `src/index.ts`
- Build output: `dist`
- Deployment: OCI image built from `Containerfile`

## Configuration

Application configuration comes from environment variables and is loaded by `src/config.ts`. Keep `example.env` synchronized when configuration keys change. Treat SASL credentials as secrets and never include them in logs or error messages.

Build metadata is generated by `scripts/generate-metadata.mjs`. Container builds must provide `GIT_COMMIT_HASH`; runtime code reads the resulting `metadata.json` for CTCP VERSION replies.

## Module Boundaries

Organize code by protocol responsibility and bot feature, not generic utility or service layers.

- `src/index.ts`: application composition, logger creation, startup, and top-level failure handling.
- `src/config.ts`: environment parsing and typed runtime configuration.
- `src/event.ts`: protocol-neutral typed event dispatch.
- `src/client`: connection lifecycle, IRC framing and parsing, event construction, and message routing.
- `src/listeners`: IRC protocol behavior, authentication flow, and bot features.
- `src/metadata.ts` and `src/shutdown.ts`: runtime metadata and graceful process shutdown.
- `scripts`: build-time tooling only; do not import it from application code.

Keep IRC transport and parsing in `client`. Keep feature-specific behavior in `listeners`. Compose listeners and client dependencies only at the application entry point.

## Design Guidance

- Prefer smallest concrete design that solves current requirement.
- Do not introduce interfaces or abstractions solely for hypothetical replacement or testing needs.
- Keep exported API surface minimal; leave module internals unexported.
- Preserve typed event relationships between event names, payloads, and listener contexts.
- Keep connection retries and waits abort-aware so SIGINT and SIGTERM shut down promptly.
- Isolate malformed server messages and listener failures without terminating the connection loop.
- Keep IRC-specific parsing explicit; avoid general parser frameworks unless current protocol needs justify them.

## TypeScript Style

- Follow existing Prettier configuration: two-space indentation, single quotes, no semicolons, and 120-column lines.
- Keep strict compiler options enabled and resolve type errors rather than weakening `tsconfig.json`.
- Include `.js` extensions in relative imports so emitted ESM works under Node.js.
- Use `import type` for type-only imports and `unknown` for unvalidated external values and caught errors.
- Prefer immutable configuration and event data with `readonly` properties.
- Use Pino child loggers for component context and structured fields for errors and metadata.
- Avoid speculative helpers, abstractions, and compatibility code.

## Security Boundaries

- Treat IRC server messages, channel messages, environment variables, and HTTP responses as untrusted input.
- Never allow carriage returns or line feeds into outgoing IRC commands; one call to `send` must produce exactly one protocol line.
- Never log SASL usernames, passwords, encoded authentication payloads, or complete `AUTHENTICATE` commands.
- Validate external API response shapes before reading fields or interpolating values into IRC messages.
- Keep TLS certificate verification enabled; do not bypass Node.js defaults.
